# Orbit

**A workspace OS for projects, tasks, documents, and schedules.**

Orbit is a product-focused workspace interface built with Next.js, React, and TypeScript. It brings projects, tasks, documents, calendar events, notifications, and workspace activity into a single operating-system-style shell.

The current version is intentionally frontend-focused. Data starts from local seed data and user changes are persisted in the browser with `localStorage`. There is no production backend, database, real-time collaboration service, or live LLM integration yet.

---

## Features

### Workspace shell

Orbit uses a persistent application shell with:

* Workspace navigation
* Project navigation
* Agenda rail
* Notifications
* Command palette
* Theme support
* Keyboard shortcuts
* Responsive layouts

The main shell is rendered through the Next.js App Router, with interactive functionality layered through client components and providers.

### Projects

Projects include:

* Status and health information
* Due dates
* Team members
* Tasks
* Documents
* Timeline/activity information
* Project-specific workspace views

Orbit also derives project-level summaries from existing workspace data.

### Tasks

The task system supports:

* Cross-project task views
* Create, update, and delete operations
* Status changes
* Priority
* Assignees
* Due dates
* Descriptions
* List and board views
* Drag-and-drop status changes
* Optimistic UI updates

Task mutations update the relevant TanStack Query caches and are persisted locally in the browser.

### Documents

The document system supports:

* Creating documents
* Editing documents
* Deleting documents
* Project associations
* Document types
* Markdown-style content editing
* Cross-project document browsing

Document updates are persisted through the same browser-local data layer used by tasks.

### Calendar

The calendar supports:

* Creating events
* Editing events
* Deleting events
* Dragging events
* Resizing events
* Moving events between time slots
* Different event types

Calendar changes are also persisted locally.

### Command palette

Orbit includes a command interface for quickly:

* Navigating between screens
* Searching workspace content
* Opening tasks, projects, and documents
* Running quick actions
* Switching themes

### Notifications

Local workspace actions can generate notifications such as:

* Task completion
* Task creation
* Document creation

Users can also mark notifications as read.

### Derived workspace intelligence

Orbit contains a deterministic intelligence layer built from pure functions.

It derives information such as:

* Projects that need attention
* Upcoming deadlines
* Blocked work
* Suggested next actions
* Task workload summaries
* Portfolio health summaries

These signals are calculated from data already available inside the application.

**They are not generated by an LLM.**

Some UI areas contain sample AI-style summary content for demonstration purposes, but Orbit does not currently call an AI model.

## Architecture

Orbit separates the interface from its data source through a Promise-based data-access layer.

```text
UI
 ↓
TanStack Query hooks
 ↓
Data-access functions
 ↓
Seed data + browser-local stores
 ↓
localStorage
```

Components depend on shared TypeScript domain types instead of depending directly on where data comes from.

This makes the data layer replaceable without requiring the UI components to be rewritten.

### Data layer

The main data-access functions live under:

```text
src/lib/data/
```

They provide async functions for retrieving:

* Users
* Workspaces
* Projects
* Tasks
* Documents
* Calendar events
* Activity
* Workspace summaries

### Browser persistence

Changes are persisted using small local stores for entities such as:

```text
tasks
documents
schedule events
notifications
```

Seed data remains unchanged while browser-created data, overrides, and deletions are layered on top.

### Client data management

TanStack Query handles:

* Queries
* Mutations
* Optimistic UI updates
* Cache synchronization between related views

For example, editing a task can immediately update both the global task list and its project detail view without waiting for a refetch.

## Authentication

Orbit currently uses a **demo cookie gate**, not production authentication.

The login flow sets a session cookie used to enter the workspace.

It does not currently include:

* User accounts stored in a database
* OAuth
* Password storage
* Production session management

---

## Persistence

Orbit currently uses browser-local persistence.

```text
Seed data
    +
localStorage overrides
    ↓
Workspace UI
```

Changes survive browser refreshes on the same browser, but data is not synchronized across devices or users.

---

## What Orbit Does Not Currently Include

To keep the current implementation accurately represented:

* No PostgreSQL or other production database
* No Prisma
* No production backend API
* No live LLM integration
* No real-time multiplayer collaboration
* No production authentication
* No server-side persistence
* No Vitest test suite in the current repository

## Project Goal

Orbit explores how a team workspace can surface the most relevant project information without turning the dashboard into another stream of noise.

The project focuses on frontend architecture, product interaction design, state management, complex interface behavior, and building a polished workspace experience with React and Next.js.
